# BACKTEST — бэктест MOEX по сетке дат

`scripts/backtest_moex.py` гоняет **полный аналитический граф** по ячейкам
(тикер × дата) и оценивает качество решений: hit rate по рейтингу и средний
alpha против **IMOEX**. Семантика повторяет `tradingagents/backtest.py`
апстрима — это **не симулятор портфеля**: ячейки независимы, объёма,
наполнения и леджера нет, их здесь и не появится (то же предупреждение, что
в апстриме). Таблица результатов — отдельный лог памяти запуска; живой
`~/.tradingagents/memory/trading_memory.md` не трогается.

## Запуск

```bash
# план сетки: сколько ячеек и какие даты (без сети и без LLM)
.venv/bin/python scripts/backtest_moex.py --plan

# полный прогон: 3 тикера × шаг 30 дней × 3 года ≈ 111 ячеек (~37 ч)
nohup .venv/bin/python scripts/backtest_moex.py \
  --tickers SBER,GAZP,LKOH --start 2023-10-18 --end 2026-10-17 \
  --every 30 --run-id bt_3y > /tmp/backtest_bt_3y.log 2>&1 &

# докатка после прерывания — тот же run-id (готовые ячейки пропускаются)
.venv/bin/python scripts/backtest_moex.py --run-id bt_3y …

# итог по уже закрытым записям
.venv/bin/python scripts/backtest_moex.py --run-id bt_3y --summary
```

Ключи: `--every N` — шаг сетки в днях; `--max-cells N` — остановиться после
N новых ячеек (пилот); `--cell-timeout 2700` — предел на ячейку (по
`run_timeout_seconds` живого цикла); `--analysts` — панель (по умолчанию
все четыре, как в живом цикле); `--summary` — только подсчёт.

Конфиг собирается тем же `gui.run_manager._build_config`, что и живой
прогон (те же модели из UI-состояния, depth 3, `TA_LLM_TIMEOUT=120`,
`TA_LLM_MAX_RETRIES=2`), плюс перекрытые `results_dir`/`memory_log_path`
внутри каталога запуска.

## Point-in-time (без утечки будущего)

| Слой | Гарантия |
|---|---|
| Свечи/индикаторы | история обрезается по дате ячейки (`curr_date`) |
| Снапшот в промпт | `build_moex_snapshot(..., as_of=дата ячейки)`; окно новостей снапшота обрезается по `as_of` (`snapshot_news_window`) — живой путь без `as_of` не изменился |
| Новости-инструмент | `moex_news(ticker, start, end)`: `until = min(now, конец end)` |
| Уроки §11 | живые уроки в ячейки **не** подмешиваются; видны только собственные settled-записи этого запуска через `get_past_context` |
| Settlement | окно 5 торговых дней закрывается только когда оно реально торговалось (запись остаётся pending и догоняется следующим запуском) |
| Alpha | против IMOEX через ISS (`integration/moex_settlement.py`), не SPY/yfinance |

## Скоринг

Из записей лога: `resolved` (есть исход и alpha) → по рейтингу `n`,
`hit rate` (направление × alpha > 0; Hold направления не имеет) и средний
alpha. `pending` — окно ещё не торговалось или исход не прочитался; они
в агрегат не входят. Формат и оговорки те же, что у апстрим-`summarize`:
одна модель-сэмпл на ячейку и неархивируемые ленты новостей делают цифры
индикативными, а не воспроизводимыми.

## Ограничения данных (честные, не заполняются оценками)

- **Ленты RSS не архивируются**: для ячеек 2023–2024 гг. RSS-источники уже
  не несут тех новостей; окно дат режется правильно, но фактическое
  покрытие старых дат даёт в основном T-Invest MCP (и то — что он отдаёт).
  При необходимости раздел помечается `No news found … between`, а не
  выдуманными заголовками.
- **Sentiment для MOEX**: соцсети (StockTwits/Reddit) неприменимы — промпт
  честно помечает их n/a и опирается на новости + цену/оборот.
- Баннер статуса сессии в снапшоте — текущий (сегодняшний), а не даты
  ячейки; на решение он не влияет, это единственная «живая» строка.
- Время: ячейка со всеми аналитиками ≈ 1050–1250 с; 111 ячеек ≈ 37 ч.

