# SECURITY

## Секреты

- Токен T-Invest — **только** env `TINVEST_TOKEN` / `TRADINGAGENTS_TINVEST_TOKEN`.
  Не хранится в settings.json, не попадает в Git, не выводится в API-ответы,
  журналы и логи (`/api/tinvest/status` возвращает лишь `configured: bool`).
- Ключи LLM-провайдеров — существующий механизм upstream (`gui/.env`,
  env-переменные), не изменялся.
- Перед коммитом: `git status` — в списке нет `.env`, токенов, `settings.json`
  (он в `~/.tradingagents/`, вне репозитория); `.gitignore` покрывает кэш/бэкапы.

## Реальная торговля

- Клиент создаётся по режиму §5.1 (`TInvestClient.from_mode`):
  `disabled/readonly/sandbox/live_readonly/live_trading`.
  Мутации в `readonly` и `live_readonly` отклоняются **до** отправки
  (`require_mutation`), даже если код дошёл до вызова.
- Переключение на `live_trading` требует `confirm_live: true` в том же
  запросе (`POST /api/tinvest/mode`), иначе 409; наличие токена само по
  себе ничего не включает.
- Ручная заявка требует `confirm=true` и успешного risk-check на **свежем**
  состоянии счёта. `trading.sandbox_auto_confirm` читается **только**
  при `tinvest.mode=sandbox` — настройки песочницы не действуют на реальный
  счёт (§1.1 п.14). Несовпадение `preview.environment` с `client.environment`
  → отказ.
- Авторежим (§6): выключен по умолчанию; для `live` нужны три отдельно
  хранимых разрешения (`tinvest.mode=live_trading`, `autotrade.live_confirmed`,
  `risk.automation_sandbox_only=false`), плюс kill switch, дневные лимиты
  заявок/позиций и «одно решение на тикер в день». Ручной запуск цикла
  обходит только гейт `enabled`.
- Поток авторежима в тестах не запускается: `TRADINGAGENTS_AUTOTRADE=0`.

## Повторные операции (§5.6)

- Стабильный `client_order_id` на весь жизненный цикл превью.
- Журнал попыток до/после отправки; сетевая ошибка → статус, не новая заявка.
- Пополнение/закрытие счёта — только с явным подтверждением в UI
  (двухшаговый диалог: сумма/валюта → confirm).

## Внешний контент (§13)

- Новости — недоверенные данные: парсятся как данные, инструкции в тексте
  не исполняются; длина ограничена (summary 700 символов, отчёты — лимитами
  агрегатора); HTML вычищается.
- HTTP: таймауты, ограниченные ретраи, изоляция ошибок по источникам;
  недоступность ≠ пустой успешный ответ (статус `error` виден в GUI).
- TLS: используется certifi; для российских сайтов добавлен
  Russian Trusted Root CA (+Sub CA) в `tinvest/certs/`,
  сборка бандла — `tinvest.client.cert_bundle()`.

## Риски, которые остаются

- Злоумышленник с доступом к env может послать заявки — а объём того, что
  можно послать, ограничивает режим §5.1 (`readonly`/`live_readonly` не пишут
  ничего, `sandbox` пишет только в песочницу). Это ограничение модели
  «токен = право на запись».
- Включённый авторежим в `live` торгует без пошагового участия оператора
  внутри цикла — защита там **до** цикла (гейты), а не после; дневные лимиты
  и kill switch ограничивают последствия, но не отменяют сделку, уже
  отправленную брокеру.
- Программное сопровождение позиций (если будет включено) не гарантирует
  исполнение на цене при гэпах/остановках торгов.
